Reproduce the corrected CV22 OpenRISC boundary discovery

This diagnostic is for compatibility-layer reverse engineering; it is not an inference command. It requires a QEMU OpenRISC build produced from third_party/patches/qemu-or1k-cv22.patch with CPU model ambarella-cv22. The exact firmware remains immutable; each generated probe is independently hashed.

.venv/bin/python scripts/discover_openrisc_boundaries.py \
  --firmware fixtures/vendor/cv22/cavalry.bin \
  --qemu /path/to/qemu-system-or1k \
  --trace-dir evidence/compatibility/openrisc-discovery-run-002 \
  --max-iterations 32 \
  --timeout-seconds 0.5 \
  --out evidence/compatibility/openrisc-discovery-run-002.json

The recorded run produced 23 trace-proven boundaries. Correct OpenRISC opcode classification is: 0x07 and 0x10 are unallocated, 0x1c = l.cust1, and 0x1f = l.cust4. The corrected profile proves +4 call/return and not-taken conditional fallthrough; the run still ends with timeout_without_illegal_instruction_boundary and fidelity_gate=failed_by_construction.

Do not use the patched probes as model output. Replacing earlier trap words with l.nop 0 proves only that later addresses are reachable under a deliberately altered execution. It does not implement those words or preserve accelerator behavior. Corrected report: evidence/compatibility/openrisc-discovery-run-002.json. Correction reconciliation: evidence/compatibility/openrisc-control-flow-correction.json. Twenty-one run-001 context snapshots are superseded. Verification: 27 focused checks passed.
